## 1. The objective function

**Formula.** For reads r_1..r_n with lengths l_i and the overlap ov(i, j) (the longest suffix of r_i equal to a prefix of r_j, at least tau letters, else 0):

```
F(pi)  = sum over k=1..n-1 of ov(pi_k, pi_{k+1})          (maximise)
L(pi)  = (sum of all l_i) - F(pi)                         (minimise)
```
**Meaning.** F is the number of letters saved by gluing the reads in the order pi; L is the length of the merged text. Maximising F and minimising L are the same goal.

**Example** (reads ATGCG, GCGTA, GTACC; total length 15): the order ABC has F = 6, L = 9 (merged text `ATGCGTACC`); the order CBA has F = 1, L = 14.

**Why it is a TSP.** With a dummy node 0 and costs c(i,j) = l_j - ov(i,j), c(0,j) = l_j, c(i,0) = 0, a round trip 0 -> pi_1 -> ... -> pi_n -> 0 costs exactly L(pi) (proof in `docs/OBJECTIVE_FUNCTION.md` section 4). Costs are not symmetric: asymmetric TSP.

## 2. Solution representation

A solution is a **permutation** of the reads (an array of read numbers). The solvers work on the cycle form: nodes 0..n, node 0 the dummy, read i = node i+1; a tour is an array t of length n+1 with t[0] = 0. The search space has n! elements. Delta evaluation: a swap or an insert changes at most six overlaps, so the change of F costs constant time (`genomeasm/solvers/moves.py`).

## 3. The data-loading pipeline (with file names)

1. `configs/genomes.yaml` lists the versioned accessions (NC_001422.1, NC_001416.1).
2. `genomeasm data fetch` (the only step with internet): `validate_accession()` then `fetch_from_ncbi()` (Entrez esummary for the facts, efetch for the FASTA text).
3. `parse_single_record()` and `Genome.from_record()`: exactly one record, header equals the accession, only A, C, G, T (decision D-016).
4. Cross-checks with NCBI: accession version, molecule type, length.
5. Atomic save: `data/raw/<acc>.fasta` (NCBI's exact bytes), `data/raw/<acc>.meta.json` (NCBI's summary plus download provenance), `data/raw/SHA256SUMS`.
6. Every normal run: `load_genome()` checks the SHA-256 of the file against `SHA256SUMS` (error `ChecksumMismatchError` if different), parses it and compares with the metadata.
7. `genomeasm data cards` writes `data/processed/<acc>.card.json` and `.card.md` (length, GC content, base counts, fingerprints).
8. `genomeasm/simulate.py` cuts reads from a window of the genome (seeded, substitution errors) and keeps the true positions as ground truth.

## 5. Twenty questions and model answers

**1. What is the objective function?** F, the total overlap of neighbouring reads in the chosen order (maximise); equivalently L = sum of lengths - F, the merged length (minimise).

**2. Why are maximising F and minimising L the same?** Each glue saves exactly ov letters (induction over the order), so L = sum(l_i) - F; the sum of lengths is a constant.

**3. Why is this a travelling salesman problem?** With a dummy node and costs l_j - ov(i, j), every round trip through all reads costs exactly L of its order; the cheapest trip is the best assembly.

**4. Why asymmetric?** ov(i, j) differs from ov(j, i): the end of i matching the start of j says nothing about the reverse.

**5. What is the solution representation?** A permutation of the reads; tours are arrays with the dummy node 0 first. n! orders.

**6. Why make the reads substring-free?** A read inside another read adds no information and breaks the overlap definition; duplicates and contained reads are dropped and counted.

**7. What are tau and the tolerance, and how were they chosen?** tau is the minimum overlap (20), the tolerance the share of mismatches allowed (0.05); tau lies above chance overlaps, the tolerance covers the simulated errors (D-027, D-036).

**8. What is coverage and what does Lander-Waterman say?** Coverage c = reads x length / genome. The expected share of uncovered letters is exp(-c); our exact model adds the edge effect of short windows, and the simulator was validated against both.

**9. How do you know the genome data are right?** NCBI RefSeq records, checked against NCBI's own metadata at download, stored with SHA-256 and verified on every load; nothing is made up.

**10. Why these two genomes?** Small, complete, public, with known answers: phiX174 (5,386 letters) and lambda (48,502). Tuning uses phiX174 only; evaluation uses lambda and other phiX174 positions.

**11. Which solvers did you compare, and why LKH-3?** Greedy, tabu search, ALNS (with five selection rules) and LKH-3, the state-of-the-art TSP heuristic, as the reference. Every LKH-3 tour is verified.

**12. What is ALNS?** Adaptive large neighbourhood search: destroy part of the order (random, worst-connected, a stretch), repair it (greedy or regret insertion), accept by simulated annealing: six tools.

**13. What is a bandit and what is UCB1?** A rule for choosing among actions of unknown, changing value. UCB1 picks the arm with the largest average reward plus c*sqrt(2 ln N / n_a), a bonus for rarely tried arms.

**14. Why not try all orders?** n! explodes: for 20 reads there are 2,432,902,008,176,640,000 orders.

**15. How did you make the comparison fair?** Same read sets, same 8 s wall-clock for every solver (LKH-3's overhead subtracted), tuning on separate data with equal effort, pre-registered primary tests, paired statistics.

**16. How were the hyper-parameters chosen?** Random search with 24 trials per algorithm on 18 tuning read sets; trial 0 is the default. The best of 24 noisy trials is optimistic (winner's curse), the same for all methods.

**17. Which statistics, and why?** Gap to the best known per read set; paired Wilcoxon (no normality needed), Holm correction within each family, bootstrap intervals, and A12 as effect size (0.5 = no difference).

**18. What did you find?** The claim is not supported: UCB1 vs random p = 0.90, A12 = 0.52; epsilon-greedy is slightly worse (A12 = 0.46). ALNS beats greedy and tabu; LKH-3 was never beaten.

**19. Why did the bandit not win, and what was the bug?** Hypotheses (not tested): six similar tools, sparse rewards. Separately, our UCB1 always played the first tool once rewards were equal (60% of its uses); with random ties it is slightly better than random (A12 = 0.57) but that is exploratory.

**20. What are the limits of your conclusions?** Two small viruses, substitution errors only, one strand, one laptop; 'best known' is not a proven optimum; two post-hoc variants; tuning set small.
